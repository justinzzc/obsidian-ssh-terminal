# Profile 设置列表与弹窗设计

## 背景

当前插件设置页会依次展开每个 SSH Profile 的完整表单，并在列表末尾继续展开新增表单。Profile 数量增加后，页面会变得冗长，连接之间也不易快速浏览。

本次调整将 Profile 管理改为紧凑列表，并使用弹窗完成查看、新增和编辑。现有 Profile 数据结构、连接逻辑及 Inline SSH 主机信任管理不变。

## 目标

- 设置页以紧凑列表展示已有 Profile。
- 点击列表项后，在弹窗中直接查看和编辑完整连接信息。
- 通过同一种弹窗新增 Profile。
- 保留现有保存、删除和忘记主机指纹能力。
- 降低页面长度，同时不增加常用操作步骤。

## 非目标

- 不改变 Profile 的持久化格式或字段定义。
- 不改变密码保存和读取机制。
- 不改变 SSH 连接、会话复用或终端行为。
- 不重做 Inline SSH 主机信任区域。
- 不引入批量编辑、排序、搜索或导入导出功能。

## 页面结构

设置页顶部继续展示现有安全说明。

Profile 区域由以下元素组成：

1. 区域标题及右侧的“新增连接”按钮。
2. 已有 Profile 的紧凑列表。
3. 无 Profile 时的空列表提示。

每个列表行展示：

- Profile 显示名称，作为主要信息。
- `username@host:port`，作为连接摘要。
- Profile ID，使用弱化样式展示。
- “查看/编辑”按钮。

点击列表行或“查看/编辑”按钮都会打开对应 Profile 的编辑弹窗。列表页不再直接渲染 Profile 表单，也不再在页面底部展开新增表单。

Inline SSH 主机信任区域保持现有位置和行为。

## Profile 弹窗

新增和编辑共用一个 `ProfileModal`。

弹窗打开后直接进入可编辑状态，不设置额外的只读模式。表单继续提供现有字段：

- Profile ID
- 显示名称
- 主机
- 端口
- 用户名
- 超时
- 密码

编辑已有 Profile 时，Profile ID 只读；新增 Profile 时，Profile ID 可填写。

编辑已有 Profile 时，密码输入框初始为空，并明确提示留空会保留现有密码。弹窗不得把已保存密码回填到输入框。

弹窗底部提供“取消”和“保存”。编辑已有 Profile 时还提供“忘记主机指纹”和“删除连接”：

- 忘记主机指纹继续调用现有 controller 能力。
- 删除连接继续要求二次确认。
- 危险操作在视觉上与主要保存操作分离。

## 数据流与职责

`SshSettingsTab` 负责：

- 获取并渲染 Profile 列表。
- 响应新增和编辑入口。
- 创建 `ProfileModal`。
- 在弹窗成功保存或删除后刷新设置页。

`ProfileModal` 负责：

- 渲染 Profile 表单。
- 管理当前输入值和字段状态。
- 调用由设置页提供的保存、删除和忘记指纹操作。
- 展示校验或操作错误。
- 成功保存或删除后关闭自身。

`SshSettingsController` 继续负责现有业务操作：

- `save(profile, password)`
- `delete(profileId)`
- `forgetHostKey(profileId)`

弹窗不复制持久化和业务规则。

## 成功与失败行为

- 保存成功：关闭弹窗并刷新 Profile 列表。
- 删除成功：关闭弹窗并刷新 Profile 列表。
- 忘记主机指纹成功：保留弹窗，可显示现有通知反馈。
- 校验或保存失败：弹窗保持打开，展示错误，并保留用户输入。
- 删除或忘记指纹失败：弹窗保持打开并展示错误。
- 用户取消：直接关闭弹窗，不保存修改。

## 样式与可用性

- 列表行使用紧凑的主次信息层级，避免再次形成大卡片表单。
- 整行可点击，同时保留显式“查看/编辑”按钮，兼顾可发现性。
- 点击行内按钮时不得重复触发行点击事件。
- 按钮和表单沿用 Obsidian 原生设置组件与主题变量。
- 空列表状态应明确提示用户使用“新增连接”创建第一个 Profile。

## 测试策略

单元测试覆盖以下行为：

- 设置页以列表形式展示 Profile，不再直接展开完整表单。
- “新增连接”打开空白 Profile 弹窗。
- 点击已有 Profile 打开预填弹窗。
- 编辑弹窗中的 Profile ID 为只读，新建时可编辑。
- 编辑已有 Profile 时密码不回填，留空沿用现有保留语义。
- 保存调用正确的 controller 参数，成功后关闭弹窗并刷新列表。
- 删除经过确认后调用正确的 controller 方法。
- 忘记主机指纹调用正确的 controller 方法。
- 操作失败时弹窗保持打开并展示错误。
- 行内按钮不会造成一次点击打开多个弹窗。

为支持弹窗测试，可以按需扩展 Obsidian 测试 mock，使其提供 `Modal` 及可触发的输入、按钮事件；扩展范围仅限本功能测试所需能力。

## 验收标准

- 设置页不再为每个 Profile 展开完整字段。
- 用户能从紧凑列表识别连接并打开编辑弹窗。
- 用户能通过“新增连接”弹窗创建 Profile。
- 原有保存、删除和忘记主机指纹功能可用。
- 错误不会导致弹窗意外关闭或用户输入丢失。
- Profile schema、SSH 连接行为和 Inline SSH 信任管理没有变化。

# Obsidian SSH Terminal 插件设计

## 1. 目标

实现一个仅支持 Obsidian 桌面版的插件，使用户可以通过 Markdown 代码块，在阅读视图和实时预览模式中打开完整交互式 SSH 终端。

首版成功标准：

- 用户可以在插件设置中创建 SSH 连接配置。
- 文档只引用连接配置名称，不包含密码。
- 用户点击“连接”后，可以在文档内获得支持持续输入的交互式 Shell。
- 阅读视图与实时预览均能渲染终端。
- 密码由操作系统钥匙串保存，服务器主机密钥经过首次信任和后续校验。
- 文档关闭、代码块销毁或插件卸载时，相关连接得到可靠清理。

## 2. 非目标

首版不支持：

- Obsidian 移动端。
- SFTP、文件上传和下载。
- 本地或远程端口转发。
- 跳板机、多跳代理和 ProxyCommand。
- 私钥认证、SSH Agent 和 `~/.ssh/config` 解析。
- 自动连接。
- 命令历史或终端输出持久化到 Markdown。
- 多个视图之间无缝迁移正在运行的终端 UI。

这些能力可以在现有接口之上逐步增加，但不进入首版范围。

## 3. 用户体验

### 3.1 连接配置

用户在插件设置页创建连接配置，包含：

- 唯一且稳定的 profile ID，使用便于阅读的 slug，例如 `production-server`。
- 可修改的显示名称。
- 主机名或 IP 地址。
- 端口，默认 `22`。
- 用户名。
- 连接超时时间，默认 `15` 秒。

密码单独写入操作系统钥匙串。插件的 `data.json` 只保存非敏感字段和已经确认的服务器主机密钥指纹。

### 3.2 Markdown 语法

插件注册 `ssh` 代码块：

````markdown
```ssh
profile: production-server
height: 360
```
````

字段规则：

- `profile`：必填，连接配置唯一且稳定的 profile ID。
- `height`：可选，终端高度，单位为像素；默认 `360`，限制在 `180` 到 `900` 之间。
- 未知字段显示为配置错误，避免拼写错误被静默忽略。

Markdown 中不允许出现密码。即使用户写入 `password` 字段，解析器也会拒绝并显示安全提示。

### 3.3 终端交互

代码块初始显示目标主机摘要和“连接”按钮，不自动发起网络请求。连接成功后显示：

- 连接状态与目标地址。
- `xterm.js` 交互式终端。
- “断开”“重连”和“清屏”操作。

终端支持文本选择、复制、粘贴、ANSI 颜色和随容器宽度自适应。终端获得焦点后，键盘输入发送给远端 PTY；按 `Escape` 将焦点交还给 Obsidian 编辑器，避免用户被困在终端中。

视图从实时预览切换到阅读视图时，旧渲染实例及其会话会被关闭。新视图重新显示未连接状态，并要求用户再次点击“连接”。插件不会在隐藏视图中保留意外运行的会话。

## 4. 技术方案

### 4.1 总体方案

插件直接在 Obsidian 桌面端进程中运行 SSH 客户端：

- `ssh2` 实现 SSH 协议、密码认证和 PTY Shell。
- `xterm.js` 与 fit addon 实现终端渲染和尺寸计算。
- Obsidian Markdown 代码块处理器实现阅读视图。
- CodeMirror 6 ViewPlugin 与 WidgetType 实现实时预览。
- `keytar` 连接 Windows Credential Manager、macOS Keychain 和 Linux Secret Service。

原生钥匙串依赖按目标平台和架构随插件发行物打包。若当前系统无法加载钥匙串实现，插件禁止保存密码，也不会降级到明文或可逆的本地配置存储。

### 4.2 模块边界

#### `ProfileStore`

负责连接配置的增删改查、字段校验和持久化。它不接收或返回密码，只通过稳定的 profile ID 与 `CredentialStore` 关联。

#### `CredentialStore`

定义 `setPassword(profileId)`, `getPassword(profileId)` 和 `deletePassword(profileId)`。生产实现调用系统钥匙串，测试实现使用内存存储。钥匙串服务名固定为插件 ID，账户名使用 profile ID。

#### `HostKeyStore`

保存每个 profile 已确认的主机密钥算法和 SHA-256 指纹。首次连接返回“待确认”结果；用户明确确认后才继续认证。后续指纹不匹配时立即终止连接，且不能通过普通“重连”按钮绕过。

#### `SshSession`

封装单个 `ssh2.Client` 生命周期。职责包括连接、主机密钥校验、密码认证、申请 PTY、读写数据、调整行列数、超时控制和幂等关闭。

状态机为：

`idle -> verifying-host -> authenticating -> connected -> disconnecting -> closed`

任一连接阶段可以进入 `failed`；`failed` 经过显式重连创建新的连接尝试。

#### `SessionManager`

以渲染实例 ID 管理活动会话。一个代码块渲染实例最多对应一个 SSH 会话。它负责防止重复点击产生并行连接，并在渲染实例卸载或插件卸载时关闭会话。

#### `TerminalView`

提供与 Obsidian 视图机制无关的 DOM 组件。它组合连接工具栏、状态提示和 `xterm.js`，并通过接口调用 `SessionManager`，不直接访问配置文件或钥匙串。

#### `MarkdownRenderer`

使用 Obsidian 的 Markdown 代码块处理器解析 `ssh` 块，并挂载 `TerminalView`。注册清理回调，在阅读视图销毁时释放终端和会话。

#### `LivePreviewExtension`

识别实时预览中的 fenced `ssh` 代码块，并用 CodeMirror Widget 挂载同一个 `TerminalView`。当光标进入代码块准备编辑配置时显示源码；光标离开后恢复终端组件。Widget 销毁时执行与阅读视图相同的清理流程。

## 5. 数据流

1. 渲染器解析代码块并校验 `profile` 与 `height`。
2. `ProfileStore` 解析 profile；不存在或无效时直接显示错误，不创建会话。
3. 用户点击“连接”。
4. `SessionManager` 创建 `SshSession` 并锁定连接按钮。
5. `CredentialStore` 从系统钥匙串读取密码。
6. `SshSession` 建立 TCP/SSH 连接并校验服务器主机密钥。
7. 首次见到的指纹由 UI 展示，只有用户确认后才继续；不匹配的已知指纹直接阻断。
8. 认证完成后申请带 `xterm-256color` 的 PTY Shell。
9. SSH 输出写入 `xterm.js`，终端输入写入 SSH stream。
10. fit addon 计算终端行列数，并通过 SSH window-change 请求同步。
11. 断开或组件销毁时，依次关闭 stream、SSH client、终端监听器与 DOM 资源。

## 6. 安全设计

- 密码只存在于系统钥匙串和连接过程的短生命周期内存中。
- Markdown、Obsidian `data.json`、错误信息和调试日志不得包含密码。
- 主机密钥采用 SHA-256 指纹并执行首次信任（TOFU）；指纹变化默认阻断。
- 日志仅记录 profile ID、连接阶段和经过归类的错误码，不记录输入命令和终端输出。
- 所有文档都可能引用已有 profile，但只有用户点击按钮才会建立连接。
- profile 删除时同步删除其钥匙串密码和已保存指纹。
- 插件卸载和禁用时关闭全部活动连接。
- 不提供“不安全地忽略主机密钥验证”的选项。

## 7. 错误处理

UI 使用稳定、可理解的错误类别：

- 配置不存在或代码块格式错误。
- 系统钥匙串不可用或密码不存在。
- DNS、网络不可达或连接超时。
- 首次主机密钥待确认。
- 主机密钥发生变化。
- 用户名或密码认证失败。
- PTY/Shell 创建失败。
- 远端主动断开。
- 插件或视图主动关闭连接。

错误显示在终端容器顶部，并保留“重连”入口；安全错误必须先在设置页完成确认或更新，不能直接重试绕过。

## 8. 并发与资源生命周期

- 每个渲染实例最多一个连接尝试和一个活动会话。
- 同一 profile 可以被多个代码块分别连接，每个块拥有独立 PTY。
- 重复点击连接按钮不会创建并发连接。
- 断开操作是幂等的，可安全处理网络错误与视图销毁同时发生的情况。
- ResizeObserver、xterm 监听器、SSH stream 和计时器都由渲染实例的 disposable 集合统一释放。

## 9. 测试策略

### 9.1 单元测试

- YAML 子集解析、必填字段、未知字段和高度边界。
- Profile 校验和 profile 删除清理逻辑。
- 会话状态转换、重复连接保护和幂等关闭。
- 主机密钥首次确认、匹配和变化阻断。
- SSH 底层错误到用户错误类别的映射。
- 日志脱敏。

### 9.2 集成测试

使用本地 Docker SSH 服务验证：

- 密码认证成功与失败。
- PTY 命令输入、输出和 ANSI 控制序列。
- 终端尺寸变化。
- 连接超时、服务器断开和重连。
- 服务器主机密钥变化时阻断连接。

### 9.3 Obsidian 手工验证

在 Windows、macOS 和 Linux 上验证：

- 阅读视图渲染。
- 实时预览 Widget 与源码编辑切换。
- 多个代码块和多个文档并行连接。
- 文档关闭、视图切换、代码块删除、插件禁用与卸载。
- 系统钥匙串不可用时的安全失败行为。
- 终端焦点、复制粘贴、窗口缩放和主题适配。

## 10. 发布与兼容性

- 插件声明 `isDesktopOnly: true`。
- 构建分别产出 Windows、macOS 和 Linux 所需的原生钥匙串依赖；发行前在对应平台做加载验证。
- 首版不承诺移动端降级体验。
- 插件样式使用 Obsidian CSS 变量，兼容浅色和深色主题。
- SSH 与凭据后端通过接口隔离，未来可加入系统 OpenSSH 后端而不改变 Markdown 格式或终端组件。

## 11. 验收标准

当以下条件全部满足时，首版可以交付：

1. 用户能够创建密码认证 profile，且密码未出现在插件数据文件中。
2. `ssh` 代码块在阅读视图和实时预览中均显示手动连接界面。
3. 用户连接本地测试服务器后，可以持续执行交互式 Shell 命令。
4. 调整 Obsidian 窗口后，远端 PTY 尺寸随之更新。
5. 首次主机密钥需要确认，已确认指纹变化会阻止连接。
6. 断开、删除代码块、关闭文档和禁用插件均不会遗留活动 SSH 连接。
7. 钥匙串不可用时，插件不会以明文或弱加密方式保存密码。
8. Windows、macOS 和 Linux 的目标发行包均通过基本连接验证。
